# CloudPlay V2 · 六页面高保真产品设计说明

版本：V2.0（视觉与交互设计稿）  
日期：2026-11-03  
参照：用户提供的 Boosteroid 桌面游戏库截图。该版本不是对 Boosteroid 的源代码或内部逻辑复刻，而是以其深色、密集游戏封面网格和顶栏交互作为视觉基线，适配纯 Web 云游戏平台。

## 0. 设计目标与边界

**设计目标：** 登录后直接进入可浏览、可筛选、可管理的云游戏工作台，用户的主要行为是「找游戏、看资格、启动游戏、管理会话」。避免营销型首屏、巨幅 Banner 和复杂侧边栏。

**交付：** 单文件离线 HTML 交互原型、My Games / Library / Game Detail / Install / Player / Admin 六页、桌面及移动端的真实浏览器渲染截图、页面状态规范和组件设计约束。

**实现边界：** 目前所有游戏目录、封面、节点数、性能指标及账户数据均为静态设计示例；没有真实 API、游戏许可验证、GPU 会话、游戏安装、支付或 WebRTC 串流。截图上的商业游戏只作为产品 UI 占位，不代表具备托管或分发授权。封面素材从用户提供的参考图片中裁切，实际产品发布前需要更换为具有相应使用许可的内容。

## 1. 总体设计系统

### 1.1 应用容器

- **顶栏**：60px，铺满宽度；品牌位于左侧，搜索、状态、通知与账户在右侧。Web 版本不绘制假的 Windows 最小化 / 关闭按钮。
- **主内容区域**：最大宽度 1900px；宽屏左右边距约 5.1vw，普通桌面边距 36–54px，移动端 15px。
- **一级导航**：MY GAMES、LIBRARY、INSTALL、ADMIN，使用窄下划线标识当前区块。ADMIN 在生产环境应按角色显示，普通用户可在设计配置中隐藏。
- **筛选工具栏**：在网格页和 Tabs 并排；布局变窄时下一行；手机端横向滚动，不强制占据三行。
- **卡片网格**：方形 `aspect-ratio:1/1`，与参考图一致；大屏 7 列，宽屏 6 列，中屏 5/4 列，手机 2 列。封面承载游戏标题，卡片下方保留极简状态标签。
- **鼠标/键盘行为**：卡片 hover 才显示主要操作；焦点仍可通过 Tab / Enter 触达；触摸设备直接点击卡片进入详情。

### 1.2 色彩与字级

| Token | 设计值 | 用途 |
|---|---|---|
| `--bg` | `#090A16` | 主底色，接近截图蓝黑色 |
| `--top` | `#161923` | 顶栏 |
| `--panel` | `#161A28` | 次级容器 |
| `--panel2` | `#1D2231` | 表单、占位和卡片 |
| `--stroke` | `#2A3040` | 分割线、边框 |
| `--white` | `#F7F8FC` | 主文字 |
| `--sub` | `#9BA1B2` | 解释文字 |
| `--blue` | `#3AAEF3` | 主 CTA、选中状态、焦点 |
| `--green` | `#28CA76` | 免费 / 通过状态（语义需分开） |
| `--amber` | `#EEB46E` | 排队、待处理、审查 |
| `--red` | `#EC6477` | 错误、拒绝、不可用 |

- 字体：系统字体栈，以 Inter / Segoe UI / 中文系统字体为主；避免 Web 引用不可控的外部字体资源。
- 顶部 Tabs：13px 高对比全大写；筛选器：12px；卡片下状态：10px；标题 27–49px（依页面尺度）。
- 组件圆角：游戏卡片 8px，操作控件 4–5px，信息面板 9px。无大面积彩色卡片，尽量贴近截图的克制观感。
- 触摸设备真实开发应把主要点击区域优化为约 44px 以上，并提供 focus-visible 与键盘退出支持。

## 2. My Games / 我的游戏

### 产品任务

为登录用户提供高频、拥有、收藏或最近启动游戏的统一入口。与「所有可见游戏」不同，`My Games` 应从 `favorite`、已验证的游戏使用资格和近期游玩记录计算，而不是简单复制 `Library` 全量数据。

### 信息层级

1. 共用顶栏：Logo、搜索、连接状态、通知、头像。
2. Tab 导航：`MY GAMES` 高亮，`LIBRARY / INSTALL / ADMIN` 可访问。
3. 紧凑筛选：Free、Controller、游戏平台、类型、排序。
4. 游戏封面网格：封面、来源平台角标、简短状态；hover 展示操作。
5. 自适应卡片数量：桌面优先信息密度；手机 2 列并显示卡片名称，避免仅凭封面辨认。

### 功能与交互

- 默认范围：最近游玩、收藏、用户拥有使用许可的游戏的并集，去重后展示。
- 游戏点击：打开详情；主要 hover 操作不直接隐式运行云游戏，而是先验证权限和会话能力。
- 添加/取消收藏：立即更改前端 My Games 集合；后端落地时用幂等写入。
- 空状态：说明还没有个人游戏，并提供「浏览游戏库」入口。
- 状态注意：`Free`、`Installed`、`License Required` 是**不同语义维度**，产品上不能把 `Free` 理解为已获云端商业托管授权。

### P0 验收

主界面在 1920px 接近参考截图的 7 列封面布局；检索和筛选可正确作用于当前个人游戏集合；卡片可键盘进入详情；移动端无横向页面溢出。

## 3. Library / 游戏库

### 产品任务

承担游戏发现和筛选。不使用巨幅 Hero 干扰浏览，打开页面时立即看到大量游戏封面。

### 信息层级

- 当前 Tab 为 `LIBRARY`。
- 右侧 `Free`、`Controller`、`All Platforms`、`All Genres`、`Popular`。
- 游戏总数和数据说明使用低对比度的轻提示，不占主视觉。
- 游戏网格与 My Games 同构，但数据范围是所有已登记的游戏。

### 筛选语义

| 筛选 | 规则 |
|---|---|
| Free | 只显示免费获取或免费游玩的游戏，绝不直接等于云游戏许可已通过 |
| Controller | 游戏具备已知手柄支持；若未经过实际串流测试，应有 `未验证` 能力状态 |
| Platform | 过滤游戏所属商店或发行平台，不能暗示已实现账户授权同步 |
| Genre | 使用规范化游戏类型，不依赖封面文字识别 |
| Popular | 应来自真实、可解释的热度数据；原型使用静态示例值 |
| Search | 对标题做大小写不敏感搜索；生产版支持别名、语言和拼写容错 |

### 状态与失败反馈

- 无搜索结果：展示重置条件按钮，不留纯空白。
- 图片失败：展示中性背景和文本标题，不让卡片塌陷。
- 分类值未知：进入「所有类型」，不要把未知映射到 Action。
- 加载与翻页：初期本地少量数据足够；大规模游戏库使用服务端搜索、分页与图像 CDN。

## 4. Game Detail / 游戏详情

### 产品任务

把「这是什么游戏」与「我能不能在这里玩」分开讲清楚。

### 页面分区

1. **面包屑**：`LIBRARY / 游戏名称`，可返回原筛选结果。
2. **主视觉**：左边方形游戏封面；右边游戏名称、类型、输入方式、概览和操作按钮。
3. **主 CTA**：不是无条件 `PLAY NOW`，而是 `查看启动预检 / 检查接入要求`，由真实资格与节点状态决定。
4. **辅助 CTA**：收藏 / 已收藏、返回游戏库。
5. **功能特性面板**：浏览器兼容、操作模式、云端 GPU 会话。
6. **Cloud Availability 面板**：商店来源、用户游戏资格、节点安装、节点资源、游戏托管权利状态。

### 启动前预检弹层

应分别核实以下环节：

- 浏览器安全上下文、媒体解码支持、WebRTC / WebCodecs 能力；
- 键鼠 / 手柄支持以及全屏和 Pointer Lock 权限；
- 平台是否能够合法提供该游戏云端访问、用户是否具备必要使用资格；
- 节点区域、GPU 空闲槽位、主机服务状态、游戏版本和存档位置；
- 连接所需的短期有效凭证、超时和取消途径。

预检通过不等于已经建立串流；必须收到真实可解码视频流、音频和输入确认，才能展示 `STREAMING`。

### P0 失败状态

许可未知、资源不足、客户端不兼容、安装不完整、编码器失败、ICE 超时、游戏启动失败等需要分别呈现，可重试项与不可重试项用不同 CTA。

## 5. Install / 云端游戏资源

### 产品任务

解释并管理「游戏安装到云端服务器」而非「下载安装到用户电脑」。MVP 可以公开只读状态；写入操作与部署操作应该由有权限的管理员执行。

### 页面分区

- 页头：`Cloud Install`，明确不是用户本地安装。
- 已配置游戏：封面、名称、来源、安装状态、版本校验，提供查看详情。
- 候选游戏：待审核 / 待部署 / 等待资源，允许查看要求。
- 右侧资源卡：GPU 节点状态、部署队列、游戏资源入库规则。

### 游戏资源状态机

`DISCOVERED` → `SOURCE_VERIFIED` → `RIGHTS_REVIEWED` → `STAGED` → `INSTALLED` → `LAUNCH_TESTED` → `READY`

异常分支：`REJECTED`、`INSTALL_FAILED`、`VERSION_MISMATCH`、`DEPRECATED`。每一步的审计证据必须可追踪。

### 权限边界

普通用户不应有任意 URL 下载、任意命令执行、任意本地磁盘路径配置权限。管理员发布安装任务之前，需要白名单来源、文件校验、授权审查和主机 Agent 的受限执行权限。

## 6. Player / 浏览器云游戏播放器

### 产品任务

将画面作为唯一主角：进入后所有面板退场，用户按需调出控制栏；移动端优先横屏。

### 页面分区

- 顶部返回入口与游戏名称。
- 视频主区域：真实媒体画面；连接前显示明确的等待/诊断状态。
- 右上（或左上）短状态条：分辨率、帧率目标、连接状态、地区等，但仅展示真实可用指标。
- 底部控制栏：网络诊断、手柄帮助、声音、画质、全屏、结束。
- 可选诊断面板：ICE、丢帧、编码与解码、实际输入响应。

### 建议会话阶段

1. `CONNECTING`：获取短期连接信息、建立媒体通道。
2. `BUFFERING`：等待有效关键帧、解码首帧。
3. `STREAMING`：正在收发音视频和输入，允许切换全屏。
4. `RECONNECTING`：断线后对原会话重连，不重复占用 GPU。
5. `DISCONNECTED`：会话仍保留，显示重连按钮和倒计时。
6. `ENDED`：显式退出、存档完成及资源释放。
7. `FAILED`：分类展示明确的错误原因和诊断建议。

### 输入与兼容性

- 桌面：键盘、鼠标、手柄；FPS 必须验证 Pointer Lock 和 Escape 退出。
- 手机：横屏、虚拟手柄配置与触控映射；提供可隐藏控制层。
- 音频：浏览器自动播放限制与音量设置。
- 画质：建议默认自动，手动 720p / 1080p 取决于真实协商能力。
- 无网络：不能展示伪造的 FPS / 网络延迟，使用 `—` 并标注未连接。

当前 HTML 仅实现 Player 外壳、预检弹窗、诊断开关、全屏等界面能力；不具备真实串流。

## 7. Admin / 运营控制台

### 产品任务

支持平台运营人员快速回答四个问题：还有多少 GPU 资源、有哪些活跃会话、哪些游戏可以部署、是否存在需要处理的故障。

### 页面布局

- 4 个简洁 KPI：GPU 节点、活跃会话、可用槽位、待处理告警。
- 左主列：GPU 节点表（地域、GPU、负载、在线状态）、活跃会话列表。
- 右侧列：负载曲线/柱状趋势、系统事件与告警。
- 按钮：节点详情、资源管理、事件日志，跳转到相应上下文。

### 最小权限与审计

- `viewer`: 查看节点和实时会话。
- `operator`: 重启失败会话、管理排队（需要保留审计）。
- `game_manager`: 管理已审查的游戏资源。
- `admin`: 管理节点、服务配置和访问策略。
- 游戏下载 URL、服务器命令、会话 token 不可直接出现在普通管理员前端页面。

### KPI 注意

- 指标必须有采集时间，不以 UI 上的绿色状态假装真实在线。
- `Online` 源于真实心跳，不等于串流可用；需监测 Sunshine / WebStream 服务健康。
- `Available Slots` 需要计算 GPU 显存、编码器能力、CPU、内存和会话隔离，不应简单等于 GPU 卡数量乘固定值。

## 9. 原型交互检查

在 Chromium 中通过离线载入并真实执行前端 JS 的方式检查：

- 六个桌面页面均能渲染，没有 JS pageerror。
- 六个移动页面都能渲染，390px viewport 未出现横向溢出。
- Free → Genre: Racing → 搜索 Rocket 的连续筛选可正确剩余一款游戏。
- 点击卡片 → 详情 → 启动预检弹窗 → Player 外壳可完成转场。
- Player 的网络诊断显示未连接，不显示伪造网络数值。

**未测试/未交付：** 真实游戏启动、Google/Steam 账号授权、GPU Node Agent、WebRTC 媒体质量、真实多用户权限、商业游戏许可证校验、支付或计费。这些不应因界面可以点击而被视为已经实现。

## 11. 后续工程顺序（设计向开发交接）

1. 把 HTML 原型转为 Next.js App Router + 可复用组件库，保证视觉对齐与动态路由。
2. 以开源游戏创建一个具有授权证据的真实游戏目录，替换商业占位封面。
3. 先连接 Windows Sunshine + Web 串流客户端，验证一个真实可玩的游戏。
4. 将会话创建、权限核验、GPU 独占租约、失败恢复纳入后端。
5. 完成安装资源管理、节点监控和管理员审计，再研究多用户商业化。
